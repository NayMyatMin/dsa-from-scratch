# 1346. Check If N and Its Double Exist — Tier 3 (approach)

Four families. All four are accepted, and at this problem's ceiling all four are fast enough that
the clock separates nothing that matters. The interesting difference is *where each one pays for
`i != j`*.

## Compare every pair

Two positions, two loops, `i != j` written out literally. O(n²) time, O(1) extra space, and finished
the moment you have typed it. Name it and keep it, because it is the thing every other family has to
be checked against — a brute-force answer you trust is worth more than a clever one you do not.

One variant looks like an improvement and is not. Writing `2 * x in arr` hands the inner loop to the
C code CPython implements `list` in, which reads as one operation and is not one. Time the
membership question on its own — asked once per element, with no verdict and no early exit hung on
it, so nothing but the lookup is on the clock:

```python
import timeit


def doubles_present(values):        # a count, not an answer to anything
    return sum(1 for x in values if 2 * x in values)


previous = None
for n in (500, 1000, 2000, 4000):
    odds = [2 * k + 1 for k in range(n)]
    t = min(timeit.repeat(lambda: doubles_present(odds), number=20, repeat=5)) / 20
    print(f"n = {n:>5}  {t * 1e3:8.3f} ms" + ("" if previous is None else f"   x{t / previous:.2f}"))
    previous = t
# -> n =   500     1.370 ms
# -> n =  1000     5.459 ms   x3.98
# -> n =  2000    21.934 ms   x4.02
# -> n =  4000    88.902 ms   x4.05
```

Four times the work for twice the data, three doublings running. The multiplier is the part that
reproduces — five runs put it between x3.87 and x4.18 — while the milliseconds themselves drift a
couple of per cent either way. Sizes past 500 are outside this problem and are there only to expose
the growth. `in` over a list compares one element at a time until something matches; chapter 1
section 8 has the row and the derivation.

## Ask a structure instead of a list

The fix for that row is to interrogate something that is not positional. A `set` hashes the value and
looks in one place, so a query costs the same whatever it holds — chapter 1 section 8 for the cost,
section 10 for the container and its price in memory. Build it once from `arr`, then walk `arr` and
ask each element about its partner.

Left for you, and it is the whole of the work:

- A set answers *is this value anywhere in here*. You need *is it at a position other than mine*.
  Tier 2 measured how often those differ and which single value makes them differ. Decide what you
  do about it before you write the loop, not after a test fails.
- One query per element, or two? The answer is not the same for this family as for the next one, and
  working out why is worth more than being told.

## Ask a structure holding only what you have walked past

> **The first two official hints, verbatim:** "Loop from `i = 0` to `arr.length`, maintaining in a
> hash table the array elements from `[0, i - 1]`." and "On each step of the loop check if we have
> seen the element `2 * arr[i]` so far."

Those are one family, and they are a fair description of it: the structure starts empty and grows
behind you, so it holds the elements at positions strictly before the one in hand. That buys
something real. A value at an earlier position is by construction at a *different* position, so
`i != j` is satisfied for free and the value that trapped the previous family needs no special case
at all.

The bill arrives elsewhere. Looking only backwards makes half the pairs invisible from where you are
standing, and the second hint above describes exactly one of the two questions:

```python
from itertools import product


def oracle(arr):
    n = len(arr)
    return any(i != j and arr[i] == 2 * arr[j] for i in range(n) for j in range(n))


def doubles_only(arr):
    seen = set()
    for x in arr:
        if 2 * x in seen:
            return True
        seen.add(x)
    return False


missed = [list(a) for L in range(2, 6) for a in product((-2, -1, 0, 1, 2), repeat=L)
          if doubles_only(list(a)) != oracle(list(a))]
print(len(missed), "wrong,", sum(1 for a in missed if oracle(a)), "false negatives")
print("shortest:", min(missed, key=len))
# -> 724 wrong, 724 false negatives
# -> shortest: [-1, -2]
```

724 of the 3,900 lists, every one of them a missed pair rather than an invented one, and the smallest
is two elements long. Taken on its own the second hint is not enough, and the third hint exists to
close the gap. Work out what that second question has to be before you open Tier 4 — Tier 2's
arithmetic block has everything you need to get it right, and the third hint leaves the one thing
that decides it unsaid.

## Sort a copy and halve the search

Sorted order is information, and `bisect` spends it: O(log n) per query, one copy of the values in
sorted order, and no hash table. `arr` is read-only here, so it is `sorted(arr)`, never `arr.sort()`.
Chapter 2 section 6 built these calls for *inserting* in order; this is the same machinery answering
the other question.

The trap is in the return value, and chapter 2 section 6 names it: an insertion point is not a
membership answer.

```python
from bisect import bisect_left

prices = [12, 19, 25, 31]
print(bisect_left(prices, 24), bisect_left(prices, 62))
# -> 2 4
target = 24
i = bisect_left(prices, target)
print(i < len(prices) and prices[i] == target)
# -> False
```

24 is not in that list and neither is 62, yet both calls hand back an index, and one of them is off
the end. Two steps turn an index into a verdict: check the index is in range, then check the element
there is equal. Both are yours to write. The same self-pair question from the second family comes
back here unchanged, because a sorted copy is still just a container of values.
