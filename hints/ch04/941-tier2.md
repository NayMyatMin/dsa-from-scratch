# 941. Valid Mountain Array — Tier 2 (observation)

"There exists some `i`" reads like an invitation to go looking, and it is not one. **At most one
index can ever satisfy the definition, so there is nothing to search among.** Suppose `i` works.
Its second clause says everything from `i` onward strictly falls, so for any later index `j` the
step arriving at `j` is a fall — and `j`'s own first clause needs that same step to be a climb.
Two summits cannot both be the summit. Checked over every list of length 1 to 8 drawn from
`{0, 1, 2, 3}`, all 87,380 of them: no list had two qualifying indices, ever. And on the 58
mountains inside the length-1-to-6 slice of that set, the summit value equals `max(arr)` and occurs
exactly once — a mountain's summit is its strict maximum, not merely one of its large elements.

The second observation is the larger one. Read the definition again and notice what it never does:
**every comparison in it is between two neighbours, and nothing in it ever compares two elements
that are not adjacent.** `arr[0] < arr[1] < ... < arr[i]` is a chain of adjacent steps, and so is
the falling half. A list of `n` elements has `n - 1` such steps, and each one is a climb, a fall or
a tie — three possibilities and no more, because that is the whole of what `<`, `>` and `==`
between two numbers can come to.

`n - 1` characters is a much smaller thing to hold than the list is, and the question worth settling
is whether it is enough. Reduce every list to those characters, throwing the values away entirely,
then group the lists by what they reduce to and ask whether any group holds both a mountain and a
non-mountain:

```python
from itertools import product


def verdicts(arr):
    """One character per adjacent pair, left to right: climb, fall or tie."""
    return "".join("<" if a < b else ">" if a > b else "=" for a, b in zip(arr, arr[1:]))


def by_the_definition(arr):
    """Try every index the fence allows, checking both of its clauses from scratch."""
    n = len(arr)
    return any(all(arr[k] < arr[k + 1] for k in range(i))
               and all(arr[k] > arr[k + 1] for k in range(i, n - 1))
               for i in range(1, n - 1))


groups = {}
for length in range(1, 7):
    for arr in map(list, product(range(4), repeat=length)):
        groups.setdefault(verdicts(arr), set()).add(by_the_definition(arr))

print(len(groups), "distinct sequences over the 5,460 lists")
print(sum(len(answers) > 1 for answers in groups.values()), "of them hold both answers")
# -> 346 distinct sequences over the 5,460 lists
# -> 0 of them hold both answers

for arr in ([0, 3, 2, 1], [3, 5, 5], [2, 1], [1, 2, 3, 2, 3, 2], [9]):
    print(arr, repr(verdicts(arr)))
# -> [0, 3, 2, 1] '<>>'
# -> [3, 5, 5] '<='
# -> [2, 1] '>'
# -> [1, 2, 3, 2, 3, 2] '<<><>'
# -> [9] ''
```

Not one group is split. Two lists that step the same way always get the same answer, over the same
exhaustive set the suite grades short inputs against — so the values are not merely unnecessary
here, they are invisible to the question being asked, and those `n - 1` characters carry everything
the definition is able to see. `[9]` reduces to nothing at all, which is the shortest way to say
that a one-element list gives the definition nothing to work with.

Those `n - 1` facts are where the tractability comes from, and also where the trap is. There is
nothing else about the list to know. Reading "there exists some `i`" as an instruction to try each
`i` and check both halves from scratch re-derives those same facts over and over:

```python
def literal_reading(arr):
    """Answer by the definition's own words, counting the neighbour comparisons it takes."""
    n, made = len(arr), 0
    for i in range(1, n - 1):
        rises = falls = True
        for k in range(i):
            made += 1
            if arr[k] >= arr[k + 1]:
                rises = False
                break
        for k in range(i, n - 1):
            made += 1
            if arr[k] <= arr[k + 1]:
                falls = False
                break
        if rises and falls:
            break
    return made


for n in (500, 1000, 5000):
    facts, made = n - 1, literal_reading(list(range(n)))
    print(f"{n:5d} elements  {facts:6,} adjacent pairs  {made:12,} comparisons")
# ->   500 elements     499 adjacent pairs       124,749 comparisons
# ->  1000 elements     999 adjacent pairs       499,499 comparisons
# ->  5000 elements   4,999 adjacent pairs    12,497,499 comparisons
```

Four thousand nine hundred and ninety-nine facts, twelve and a half million comparisons: each fact
established very nearly 2,500 times over. Double the input, the first row against the second, and
the count multiplies by 4.00; take five times the input, the second row against the third, and it
multiplies by 25.02. The factor squares every time, and that is the trouble. `arr.length` reaches
10^4, so this is not a stylistic preference — it is the difference between a solution and a
timeout, and both guards in `tests/ch04/test_p02_valid_mountain_array.py` exist to say so.

*Which* sequences are the accepting ones is the one thing the reduction above deliberately does not
answer, and it is the question this tier stops in front of. Work at it yourself first.
