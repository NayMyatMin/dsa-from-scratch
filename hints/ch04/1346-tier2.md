# 1346. Check If N and Its Double Exist — Tier 2 (observation)

The statement puts two positions in play at once, which makes it sound like a question about pairs.
Turn it around and hold a single element `x`. If `x` is the one being doubled, its partner has to be
`2 * x`. If `x` is the double, its partner has to be `x / 2`, and only when `x` is even. There is no
third case.

**A partner is not "one of the other elements". It is one of at most two specific values, and you
can write both of them down before looking at anything else.** Over the whole legal value range:

```python
from collections import Counter

LO, HI = -1000, 1000
sizes = Counter()
for x in range(LO, HI + 1):
    partners = {2 * x} if x % 2 else {2 * x, x // 2}
    sizes[len({p for p in partners if LO <= p <= HI})] += 1
print(sorted(sizes.items()))
# -> [(0, 500), (1, 1001), (2, 500)]
```

Two at the very most, one for the majority, and 500 legal values whose partner could not be a legal
value at all. At `n = 500` that is 249,500 ordered pairs of positions on one side, against at most
1,000 questions whose subject you already know on the other.

That is a reason to keep looking, not a reason to reject what you have. Comparing every pair is a
legitimate answer to this problem. The length stops at 500, and
`tests/ch04/test_p01_check_double_exists.py` accepts that shape unchanged and says so in its own
docstring, in the list of things it deliberately does not police:

```python
import timeit


def nested(arr):
    n = len(arr)
    for i in range(n):
        for j in range(n):
            if i != j and arr[i] == 2 * arr[j]:
                return True
    return False


worst = [2 * k + 1 for k in range(500)]      # 500 odd values, so the answer is False
t = min(timeit.repeat(lambda: nested(worst), number=5, repeat=7)) / 5
print(round(t * 1e3, 2), "ms at the constraint ceiling, worst case")
# -> 4.47 ms at the constraint ceiling, worst case
```

Every element odd means no element's double is present, so nothing exits early and the loop runs to
the end. That figure moves between runs — across fourteen it stayed between 4.3 and 5.7 ms — and the
size of it is the point. Single-digit milliseconds on the largest input the constraints permit.
**Nothing in this problem's requirements rules the pairwise version out.** The observation above
buys craft, not survival.

Two details of the arithmetic are worth settling now, because both bite later:

```python
print(10 / 2, 5 / 2)
# -> 5.0 2.5
print(5.0 in {3, 5, 7}, 2.5 in {1, 2, 3})
# -> True False
print(-3 // 2, -3 % 2, -4 % 2)
# -> -2 1 0
```

True division produces a float, and that costs nothing: `5.0` equals `5` and hashes the same, so a
container of integers finds it. An odd number's half is a non-integer, and a container of integers
correctly refuses it. Floor division has neither property — `-3 // 2` is `-2`, a perfectly ordinary
integer that may well be sitting in your data. And `%` on a negative gives a non-negative result, so
`x % 2 == 0` does identify the even numbers on both sides of zero.

The other half of the observation is `i != j`. Over the integers, `x == 2 * x` has exactly one
solution, and 0 is a legal element. So for every value but one, "is my partner present" and "is my
partner present somewhere else" are the same question — and for that one value they are not. `[0, 3]`
is False; `[3, 0, 0]` is True. Any structure that answers *is this value present* therefore answers
the wrong question exactly once:

```python
from itertools import product


def oracle(arr):
    n = len(arr)
    return any(i != j and arr[i] == 2 * arr[j] for i in range(n) for j in range(n))


def careless(arr):
    values = set(arr)
    return any(2 * x in values for x in arr)


wrong = [list(a) for L in range(2, 6) for a in product((-2, -1, 0, 1, 2), repeat=L)
         if careless(list(a)) != oracle(list(a))]
print(len(wrong), min(a.count(0) for a in wrong), max(a.count(0) for a in wrong))
# -> 456 1 1
```

456 wrong out of 3,900, and every single one of them holds exactly one zero — the minimum and the
maximum of that count are both 1. A test set that never puts a lone zero in front of you gives no
sign that anything is wrong.
