# 1089. Duplicate Zeros — Tier 2 (observation)

The collision in Tier 1 is not a disagreement about *what* to write. Every element's destination is
settled by the input alone, before you touch a single slot: the value at index `i` belongs at `i`
plus the number of zeros lying to its left, a zero's second copy belongs one slot beyond that, and
either one survives only if its landing spot is still inside the array. (Rebuilt from that rule
alone and compared against the answer the problem statement defines, over 20,000 random arrays of
length 1 to 30: zero mismatches, and never a slot the rule left unfilled.)

**So the answer is fully determined in advance, and only the order of the writes can be wrong.**
That is the whole character of this problem.

Now notice what kind of fact a destination is. Looking at `arr[i]` on its own tells you nothing
about where it goes — a 3 sitting at index 4 might not move at all, or might move as many as four
places, and the difference is decided entirely by slots you are not looking at. A destination is a
fact about a stretch of the array rather than about one element, so any walk that settles elements
one at a time has to be carrying that stretch along with it.

> **The official hint, verbatim:** "The main problem with not using additional memory is that we
> might override elements due to the zero duplication requirement of the problem statement. How do
