# 485. Max Consecutive Ones — Tier 2 (observation)

A run of 1s ends in exactly two ways. One is "the next element is a 0." What is the other?

Almost every wrong answer on this problem handles the first and forgets the second.

Find out which of the parametrized cases is failing. Run:

```bash
uv run pytest tests/ch01/test_p01_max_consecutive_ones.py -v
```

Each failure prints the case in square brackets. If it reads something like
`test_examples_and_edges[nums7-3]`, that id was generated by pytest rather than written by hand:
the cases are numbered in source order starting at 0, and the trailing number is the expected
result. `nums7-3` is therefore the eighth tuple in the parametrize list, expecting 3. Count down
to it in the test file and read the comment on its line — the comments say what each case is
there to catch. (If the id is a readable phrase instead, that is the case's own name and you can
go straight to it.)

> **The official hint, verbatim:** "You need to think about two things as far as any window is
> concerned. One is the starting point for the window. How do you detect that a new window of 1s
> has started? The next part is detecting the ending point for this window. How do you detect the
> ending point for an existing window? If you figure these two things out, you will be able to
> detect the windows of consecutive ones. All that remains afterward is to find the longest such
> window and return the size."
